# volta-tools

[English](README.md) | **Русский**

Инструменты, которые я запускаю на своих валидаторах Solana, приведённые в порядок, чтобы ими мог пользоваться любой.
Обычный bash и Python (только стандартная библиотека), systemd и штатный `solana` CLI. Собирать ничего не нужно.

## Скоро

Сейчас на моих нодах проходит тестирование большой блок: установщик валидатора, оптимизатор системы, настройка AF_XDP
и всё остальное, на чём держатся мои валидаторы. Он войдёт сюда новыми модулями того же установщика.

## Готово к продакшену

| модуль | версия | что делает |
|---|---|---|
| [vat](vat/README.ru.md) | 1.1.0 | держит на vote-аккаунте запас под VAT (Alpenglow) и выводит лишние SOL с identity на ваш кошелёк |
| [bamboost](bamboost/README.ru.md) | 1.1.0 | забирает Jito BAM Boost (JIP-31) за каждую открытую эпоху и выводит JitoSOL на ваш кошелёк |

volta-tools модульный: один установщик, один конфиг и модули, которые вы выбираете. У каждого модуля своя версия,
свой changelog и свой README: что делает, как работает, как им пользоваться.

## Установка

```bash
git clone https://github.com/VoltaEva/volta-tools ~/volta-tools
sudo ~/volta-tools/install.sh
```

Установщик сам находит юнит валидатора, ключ identity, vote-аккаунт, леджер и RPC. Спрашивает только то, чего знать
не может: кошельки выплат и, если нужны сообщения, бота Telegram. Потом спрашивает, какие модули включить. Показывает
конфиг перед записью в `~/volta-tools/.env` (chmod 600, git его игнорирует) и ставит systemd-таймеры выбранных
модулей. Ничего не запускает:

```bash
sudo systemctl enable --now volta-vat.timer volta-bamboost.timer
```

Установщик можно запускать снова в любой момент, чтобы поменять настройки: текущие значения становятся значениями по
умолчанию, и каждое изменение видно до записи. Последние 5 версий конфига хранятся как `.env.bak-<время>`. На
failover-паре ставьте на обе ноды. Цвета видны только в терминале; `NO_COLOR=1` их выключает.

Конфиг — обычные строки `KEY=value`. Он читается как данные и никогда не исполняется как скрипт: значение с пробелами
или спецсимволами пишется в кавычках, а ваши собственные строки остаются такими, как вы их написали. Установщик
никогда не запускает и не останавливает таймеры: если у модуля, который вы не включили, есть таймер, он скажет об этом
и даст команду, чтобы его выключить.

## Кошельки выплат

У каждого модуля, который платит, свой кошелёк: `VAT_PAYOUT_WALLET` и `BAMBOOST_PAYOUT_WALLET`. Установщик спрашивает
оба: укажите кошелёк для каждого модуля или только один. Модуль с пустым кошельком тогда платит на кошелёк другого и
предупреждает об этом. Без единого кошелька выплат не запускается ничего: будет ERROR, и установщик спросит снова.

Только живой кошелёк:

- он уже существует on-chain, то есть не пустой: сначала отправьте на него немного SOL;
- вы управляете им своим ключом, и этот ключ лежит не на сервере валидатора;
- не депозитный адрес биржи: bamboost выводит JitoSOL, это токен, и такой адрес может его не принять;
- не identity и не vote-аккаунт.

Подойдёт любой обычный кошелёк: приложение (Phantom, Solflare, Backpack), аппаратный кошелёк через одно из них (Ledger)
или мультисиг (Squads). Аппаратный кошелёк или мультисиг надёжнее всего: выплаты тогда не зависят от ключа, который
лежит на компьютере.

Инструменты проверяют, что могут: кошелёк должен существовать on-chain как обычный кошелёк и не может быть identity
или vote-аккаунтом, иначе модуль откажется работать. Проверить нельзя только одно: что ключ от кошелька у вас.

## Telegram

Необязательно, один бот на все модули. Переводы и выплаты идут в `TG_CHAT_ID`. Ошибки и тревоги идут в
`TG_CHAT_ALARM`, если он задан, иначе в тот же чат. Проблема не повторяется, пока остаётся той же. Каждый модуль может
выключить свои сообщения: `VAT_TG=0`, `BAMBOOST_TG=0`.

## Версии и обновления

У ядра (установщик и `lib/`) и у каждого модуля своя версия: `VERSION` в корне и `<модуль>/VERSION`, рядом changelog.

```bash
~/volta-tools/vat/vat.sh --version
~/volta-tools/bamboost/bamboost.py --version
```

Обновление:

```bash
cd ~/volta-tools && git pull && sudo ./install.sh
```

Ваш `.env` остаётся как есть, новые настройки получают значения по умолчанию.

## Требования

- валидатор Agave или Jito-Agave под systemd
- `solana` CLI на сервере (ставится вместе с валидатором)
- bash, curl, awk, flock; python3 для bamboost
- bamboost: только mainnet
