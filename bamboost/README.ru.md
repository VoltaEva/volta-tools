# bamboost

[English](README.md) | **Русский**

Валидаторы на Jito BAM каждую эпоху зарабатывают BAM Boost (JIP-31), он платится в JitoSOL. Сам он не приходит: его
нужно забрать (claim), а эпоху, не забранную за 20 эпох, Jito забирает обратно.

`bamboost` запускается раз в час и делает две вещи:

1. **Claim.** Для каждой ещё открытой эпохи берёт дерево наград эпохи из публичного бакета Jito, сам считает proof и
   сверяет корень дерева с on-chain merkle-дистрибьютором Jito: не совпало, значит claim не делается. Boost приходит
   на JitoSOL-аккаунт identity (программа платит только туда). Старые открытые эпохи забираются сразу, текущая через
   `BAMBOOST_CURRENT_AFTER_HOURS` часов после её начала.
2. **Вывод.** Переводит весь JitoSOL с JitoSOL-аккаунта identity на `BAMBOOST_PAYOUT_WALLET` (пусто: на кошелёк
   другого модуля, см. [кошельки выплат](../README.ru.md#кошельки-выплат)). JitoSOL-аккаунт кошелька создаётся первым
   выводом, платит за это identity.

Только стандартная библиотека Python 3: подпись, транзакции и proof делаются в самом скрипте, ставить ничего не нужно.

## Что защищает

- Без явного кошелька выплат не запускается даже в пробном режиме (`BAMBOOST_PAYOUT_WALLET` или, если он пуст, кошелёк
  другого модуля, с предупреждением). Только живой кошелёк: он существует on-chain как обычный кошелёк, не может быть
  identity или vote-аккаунтом, а ключ от него ваш и лежит не на сервере. Не депозитный адрес биржи: выплата идёт в
  JitoSOL, это токен.
- Прежде всего проверяет on-chain, что ключ является identity вашего vote-аккаунта.
- Подписывает только ключом identity. Отправляет только claim в программу BAM Boost и вывод на JitoSOL-аккаунт вашего
  кошелька.
- Как голосующая нода работает только там, где локальный валидатор сейчас идёт с настоящим identity. Запасная нода
  failover-пары ничего не делает, кроме страховки: эпоху, которая висит незабранной `BAMBOOST_BACKUP_AFTER` эпох
  (голосующая нода работает, но её таймер сломан), забирает запасная, и выводит она только то, что забрала сама.
- Останавливается, когда на identity меньше 0.05 SOL.
- Временные сбои повторяются (3 попытки через 10 с); перед каждым повтором проверяет, не прошла ли прошлая попытка.
  Повторный запуск всегда безопасен: эпоху можно забрать только один раз.
- По умолчанию пробный режим (`BAMBOOST_DRY_RUN=1`): подписывает и симулирует каждую транзакцию, ничего не отправляет.

## Сколько стоит

- Около 0.0009 SOL за каждую забранную эпоху: рента записи о claim (ClaimStatus). Она не возвращается: в программе нет
  инструкции, чтобы её закрыть.
- Один раз: около 0.0015 SOL за JitoSOL-аккаунт identity и столько же за аккаунт вашего кошелька при первом выводе. Это
  рента, она остаётся на этих аккаунтах.
- Комиссии транзакций.

## Установка

Запустите [установщик](../README.ru.md#установка) и включите bamboost, когда он спросит. Он берёт ключ identity,
vote-аккаунт и кошелёк выплат, которые установщик уже нашёл или спросил. Потом посмотрите пробный запуск:

```bash
~/volta-tools/bamboost/bamboost.py                 # что он забрал бы и вывел сейчас
~/volta-tools/bamboost/bamboost.py --auto --dry    # то же по логике таймера
```

У каждой открытой эпохи своя строка: `already claimed`, `OK (simulated ...)` с суммой или причина, почему эпоха
пропущена. Когда пробный запуск выглядит правильно, поставьте `BAMBOOST_DRY_RUN=0` в `~/volta-tools/.env` и запустите
таймер:

```bash
sudo systemctl enable --now volta-bamboost.timer
```

## Ручные запуски

```bash
bamboost.py --live                  # забрать открытые эпохи, потом вывести
bamboost.py --live --no-sweep       # только забрать
bamboost.py --sweep-only --live     # только вывести
bamboost.py --from 1070 --to 1075   # только эти эпохи (без --live это пробный запуск)
bamboost.py --tg-test               # тестовое сообщение в чат сообщений и в чат тревог
```

`--live` требует `BAMBOOST_DRY_RUN=0`. Без `--live` (или `--auto`) любой запуск пробный.

## Настройки

Все в `~/volta-tools/.env`, секция `bamboost`. Читаются при каждом запуске.

| переменная | по умолчанию | что значит |
|---|---|---|
| `BAMBOOST_PAYOUT_WALLET` | (спрашивается) | куда идёт JitoSOL; пусто = кошелёк другого модуля, с предупреждением |
| `BAMBOOST_RPC_URL` | публичный RPC mainnet | RPC для claim и вывода; собственный RPC валидатора подходит только с `--full-rpc-api` |
| `BAMBOOST_CURRENT_AFTER_HOURS` | случайное 10..16 | текущая эпоха забирается через столько часов после начала |
| `BAMBOOST_BACKUP_AFTER` | `10` | запасная нода забирает только эпохи, висящие незабранными столько эпох |
| `BAMBOOST_TIMER_MINUTE` | случайная | минута часа для таймера |
| `BAMBOOST_TIMER_JITTER` | `15min` | случайная добавочная задержка каждого запуска |
| `BAMBOOST_LOG_TZ` | время сервера | часовой пояс лога, например `Asia/Tokyo` |
| `BAMBOOST_TG` | `1` | сообщения Telegram от bamboost: `1` вкл, `0` выкл |
| `BAMBOOST_DRY_RUN` | `1` | `1` = только симуляция, `0` = отправлять |

Ещё он читает `IDENTITY_KEYPAIR`, `VOTE_ACCOUNT`, `RPC_URL`, `VALIDATOR_BIN`, `LEDGER_DIR` и настройки Telegram из
начала файла. После изменения `BAMBOOST_TIMER_*` запустите установщик ещё раз, чтобы таймер получил новое время.

## Логи и сообщения

```bash
journalctl -u volta-bamboost -o cat
systemctl list-timers volta-bamboost.timer
cat ~/volta-tools/.state/bamboost.log
```

Таймер что-то печатает, только когда что-то сделал. `.state/bamboost.log` хранит только настоящие действия: по строке
на каждый claim и вывод или строку с причиной, если что-то не вышло; та же строка не пишется снова, пока она среди
последних 30. WARNING приходит, когда у незабранной эпохи осталось 3 эпохи или меньше. Что попало в лог, уходит в
Telegram: claim и выводы в `TG_CHAT_ID`; сбои, предупреждения и остановки в `TG_CHAT_ALARM`.

## Failover-пары

Ставьте на обе ноды с одинаковыми ответами. Нода, которая голосует настоящим identity, забирает и выводит; запасная
только следит за эпохами, которые слишком долго висят незабранными. После переключения на следующем запуске работу
подхватывает другая нода.

## Удаление

```bash
sudo systemctl disable --now volta-bamboost.timer
sudo rm /etc/systemd/system/volta-bamboost.service /etc/systemd/system/volta-bamboost.timer
sudo systemctl daemon-reload
```
