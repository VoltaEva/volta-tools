# vat

[English](README.md) | **Русский**

С Alpenglow vote-аккаунт каждую эпоху платит VAT (0.8 SOL в mainnet), а доход с блоков приходит на identity. Если
ничего не делать, vote-аккаунт пустеет, а SOL копится на identity на горячем сервере.

`vat` запускается раз в час и делает две вещи:

1. **Пополнение.** Когда VAT на vote-аккаунте хватает меньше чем на `VAT_LOW_EPOCHS` эпох, переводит SOL с identity
   и доводит запас до `VAT_RESERVE_EPOCHS`. Identity при этом не опускается ниже `VAT_IDENTITY_FLOOR`.
2. **Вывод.** Всё, что на identity выше `VAT_IDENTITY_MIN`, уходит на `VAT_PAYOUT_WALLET`, если набралось хотя бы
   `VAT_MIN_SWEEP` (пусто: на кошелёк другого модуля, см. [кошельки выплат](../README.ru.md#кошельки-выплат)).

## Что защищает

- Без явного кошелька выплат не запускается даже в пробном режиме: `VAT_PAYOUT_WALLET` или, если он пуст, кошелёк
  другого модуля (тогда предупреждение на каждом запуске). Только живой кошелёк: он уже существует on-chain как обычный
  кошелёк, так что опечатка в адресе не съест SOL, а ключ от него ваш и лежит не на сервере.
- Подписывает только ключом identity. Withdraw authority не нужен никогда: держите его не на сервере.
- Работает только на ноде, которая сейчас голосует настоящим identity: спрашивает локальный валидатор
  (`agave-validator contact-info`). Запасная нода failover-пары с другим identity ничего не делает, поэтому vat можно
  ставить на обе ноды пары.
- Перед любым переводом проверяет on-chain, что vote-аккаунт принадлежит этому identity.
- По умолчанию пробный режим (`VAT_DRY_RUN=1`): только пишет в лог, что отправил бы.
- Одновременно идёт только один запуск.

## Установка

Запустите [установщик](../README.ru.md#установка) и включите vat, когда он спросит. Он сам находит ключ identity,
vote-аккаунт и леджер в systemd-юните валидатора (или в скрипте запуска, который вызывает юнит) и спрашивает кошелёк
выплат.

Посмотрите пробный запуск, прежде чем ставить `VAT_DRY_RUN=0`:

```
$ ~/volta-tools/vat/vat.sh --dry-run
2026-11-07T19:41:07Z vat 1.1.0 dry=1 | identity 7xKq3m 5.214000000 (keeps 3) | vote 9fPa2c 2.410000000 (top-up below 2.520000000 to 4.180000000) | payout Hs8dQv
2026-11-07T19:41:07Z vote top-up: 1.770000000
2026-11-07T19:41:07Z DRY: would send 1.770000000 SOL to <your vote account>
2026-11-07T19:41:07Z spare 0.443990000 is below VAT_MIN_SWEEP 1, nothing to sweep
```

## Настройки

Все в `~/volta-tools/.env`, секция `vat`. Читаются при каждом запуске.

| переменная | по умолчанию | что значит |
|---|---|---|
| `VAT_PAYOUT_WALLET` | (спрашивается) | куда уходят лишние SOL identity; пусто = кошелёк другого модуля, с предупреждением |
| `VAT_PER_EPOCH` | `0.83` | VAT за эпоху с небольшим запасом |
| `VAT_LOW_EPOCHS` | `3` | пополнять, когда vote-аккаунта хватает меньше чем на столько эпох |
| `VAT_RESERVE_EPOCHS` | `5` | пополнять до стольких эпох |
| `VAT_RENT` | `0.03` | минимум vote-аккаунта для освобождения от ренты, держится сверху |
| `VAT_IDENTITY_MIN` | `3` | столько остаётся на identity после вывода |
| `VAT_IDENTITY_FLOOR` | `1` | пополнение никогда не опускает identity ниже этого |
| `VAT_MIN_SWEEP` | `1` | меньшие суммы не выводятся |
| `VAT_TIMER_MINUTE` | случайная | минута часа для таймера |
| `VAT_TIMER_JITTER` | `15min` | случайная добавочная задержка каждого запуска |
| `VAT_TG` | `1` | сообщения Telegram от vat: `1` вкл, `0` выкл |
| `VAT_DRY_RUN` | `1` | `1` = только лог, `0` = отправлять |

После изменения `VAT_TIMER_*` запустите установщик ещё раз, чтобы таймер получил новое время.

## Логи

```bash
journalctl -u volta-vat -o cat
systemctl list-timers volta-vat.timer
```

## Failover-пары

Ставьте на обе ноды с одинаковыми ответами. Запасная нода раз в час пишет `not the voting node ..., skip`. После
переключения на следующем запуске работу подхватывает другая нода.

## Удаление

```bash
sudo systemctl disable --now volta-vat.timer
sudo rm /etc/systemd/system/volta-vat.service /etc/systemd/system/volta-vat.timer
sudo systemctl daemon-reload
```
